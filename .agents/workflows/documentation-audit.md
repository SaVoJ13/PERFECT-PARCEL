# РОБОЧИЙ ПРОЦЕС: АУДИТ ТА СИНХРОНІЗАЦІЯ ДОКУМЕНТАЦІЇ (DOCUMENTATION AUDIT)

> **Призначення:** Періодична перевірка відповідності проєктної документації реальному стану коду  
> **Головна мета:** Усунути розрив між специфікаціями та реалізацією, виявити застарілі дані або неавторизовані зміни.  
> **Періодичність:** Наприкінці кожного тижня або перед завершенням кожної фази.  
> **Відповідальний:** Agent 0 та Agent 5 (QA)  

---

## 1. ОБЛАСТЬ АУДИТУ (AUDIT SCOPE)

1. **Геймдизайн vs Код:**
   - Перевірити, чи кількість реалізованих рівнів відповідає `LEVEL_DESIGN.md`.
   - Чи співпадають типи посилок у коді з 5 описаними в `GAME_DESIGN.md`.
   - Чи відповідає формулювання та вартість покращень таблицям в `ECONOMY_DESIGN.md`.

2. **UI & Арт vs Реєстр ассетів:**
   - Перевірити кожен графічний файл у проекті на наявність запису в `ASSET_REGISTER.md`.
   - Перевірити відповідність назв екранів у коді макетам в `UI_SPECIFICATION.md`.
   - Перевірити правильність шрифтових ліцензій.

3. **Архітектура vs Платформа:**
   - Перевірити, чи Target SDK у `build.gradle` збігається зі значенням у `TECHNICAL_SPEC.md`.
   - Перевірити, чи немає сторонніх бібліотек, які відсутні в `ARCHITECTURE.md`.

4. **Управління проєктом:**
   - Чи актуальні списки завдань у `TASK_BOARD.md`.
   - Чи всі ключові зміни оформлені у вигляді ADR в `DECISIONS.md`.
   - Чи актуальний `CURRENT_STATE.md`.

---

## 2. ПРОЦЕДУРА ПРОВЕДЕННЯ АУДИТУ

```
[Agent 0 / QA] ──► Звіряє файли коду та ассетів із документами в docs/
       │
       ▼
[Виявлено розбіжність?]
  ├── НІ  ──► Аудит пройдено. Запис у CURRENT_STATE.md "Documentation in Sync".
  │
  └── ТАК ──► Формується "Documentation Drift Issue":
               1. Якщо застаріла документація -> оновити docs/.
               2. Якщо несанкціонована зміна в коді -> скасувати код або
                  подати на погодження Власнику.
```

---

## 3. ЗВІТ ПРО АУДИТ

Результати фіксуються короткою довідкою:
- Дата перевірки.
- Кількість перевірених документів.
- Знайдені розбіжності та статус їх виправлення.
- Підпис аудитора (Agent 5 / Agent 0).
