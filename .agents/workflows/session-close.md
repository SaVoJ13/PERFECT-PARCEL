# РОБОЧИЙ ПРОЦЕС: ЗАКРИТТЯ РОБОЧОЇ СЕСІЇ (SESSION CLOSE)

> **Призначення:** Обов'язкова стандартизована процедура фіксації стану наприкінці кожної робочої сесії  
> **Головна мета:** Забезпечити 100% збереження прогресу та безшовне відновлення контексту в наступній сесії без втрати інформації.  
> **Відповідальний координатор:** Agent 0  

---

## ЧЕКЛІСТ ЗАКРИТТЯ СЕСІЇ

### 1. Оновлення дошки завдань (`docs/governance/TASK_BOARD.md`)
- [ ] Перевірити статус усіх поточних завдань (`In Progress`, `Review`, `Done`, `Blocked`).
- [ ] Додати нові виявлені таски до беклогу.

### 2. Актуалізація поточного стану (`docs/governance/CURRENT_STATE.md`)
Agent 0 зобов'язаний зафіксувати:
- [ ] Поточна активна фаза та загальний статус.
- [ ] Список створених/змінених файлів за сесію.
- [ ] Останній хеш або опис коміту Git.
- [ ] Виявлені ризики або відкриті дефекти (P0/P1/P2).
- [ ] **Чіткі наступні 3 кроки для нової сесії.**
- [ ] Запитання, які потребують відповіді або затвердження Власника.

### 3. Фіксація в журналі сесій (`docs/governance/SESSION_LOG.md`)
- [ ] Додати запис про проведену сесію:
  * Дата та час.
  * Хто брав участь (Agent 0, Agent 1..5).
  * Короткий перелік вирішених питань.
  * Витрачений прогрес.

### 4. Фіксація архітектурних рішень (`docs/governance/DECISIONS.md`)
- [ ] Якщо під час сесії було прийнято важливе технічне або дизайнерське рішення — створити запис у форматі ADR.

### 5. Git Commit & Push
- [ ] Перевірити `git status` — жоден тимчасовий або чутливий файл (`.env`, `.keystore`) не повинен потрапити у staging.
- [ ] Зробити змістовний коміт за стандартом Conventional Commits.
- [ ] Виконати push у відповідну робочу гілку.

### 6. Підсумкове повідомлення Власнику
- [ ] Надати короткий висновок: що було досягнуто, стан готовності та що планується робити далі.
