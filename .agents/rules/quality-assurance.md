# ПРАВИЛО: ЗАБЕЗПЕЧЕННЯ ЯКОСТІ ТА СТАНДАРТИ ТЕСТУВАННЯ (QUALITY ASSURANCE)

> **Статус:** Обов'язкове для всіх AI-агентів проєкту PERFECT PARCEL  
> **Версія:** 1.4  
> **Джерело:** Розділ 11, 14, 18 Roadmap 1.4  

---

## 1. ПРИНЦИП НЕЗАЛЕЖНОГО КОНТРОЛЮ ЯКОСТІ

Жодна задача з розробки не вважається завершеною, доки вона не пройшла верифікацію **Agent 5 (QA)**. Самостійне закриття завдань розробниками (Agent 3 чи Agent 4) заборонено.

---

## 2. МЕТРИКИ ЯКОСТІ ТА КРИТЕРІЇ ПРИЙНЯТТЯ (AC)

Кожна збірка гри оцінюється за такими строгими критеріями:
1. **Стабільність (Crash-Free Rate):**
   - 0 крашів (100% стабільність) при проходженні всіх 30 рівнів.
   - Коректна обробка переривань: вхідні дзвінки, перемикання додатків, блокування екрана, відновлення гри.
2. **Продуктивність (Performance):**
   - Ціль: стабільні 60 FPS на пристроях середнього рівня (Android 10+).
   - Мінімальний допустимий поріг: не нижче 55 FPS під час спавну складних посилок і частинок.
   - Відсутність мікрофризів (GC spikes не довше 16 мс).
3. **Пам'ять та ресурси:**
   - Споживання RAM у грі: не більше 150–200 МБ.
   - Відсутність витоків пам'яті при багаторазовому перезапуску рівнів.
   - Розмір фінального APK/AAB: до 50–70 МБ для швидкого завантаження.
4. **Цілісність збереження (Data Integrity):**
   - Гарантія збереження монет, куплених апгрейдів та зірок навіть при екстреному закритті додатку.
   - Валідація схеми сейву та захист від зламаного JSON.
5. **Офлайн-готовність:**
   - 100% функціональність основного ігрового процесу без підключення до мережі інтернет.

## 3. КЛАСИФІКАЦІЯ ПОМИЛОК ТА ДЕФЕКТІВ

| Рівень | Назва | Опис | Дія |
| :--- | :--- | :--- | :--- |
| **P0** | **Блокер (Blocker)** | Краш гри, чорний екран, зависання конвеєра, пошкодження збережень, неможливість пройти рівень. | **Зупиняє роботу над новими фічами.** Негайне виправлення. Реліз заблоковано. |
| **P1** | **Критичний (Critical)** | Порушення ігрової логіки (монети не нараховуються, апгрейд не працює), просідання FPS нижче 40, збій UMP згоди. | Виправляється у поточному спринті. Реліз заблоковано до фіксу. |
| **P2** | **Мажорний (Major)** | Помилка відображення UI, накладання тексту локалізації, відсутність звуку при натисканні, некритичний глітч анімації. | Виправляється за планом. Може бути допущено до тестових білдів, але не до фіналу. |
| **P3** | **Мінорний (Minor)** | Невеликі візуальні розбіжності з макетом, орфографічна помилка, мікро-затримка закриття меню. | Виправляється за наявності вільного часу. |

---

## 4. РЕГРЕЙСІЙНЕ ТЕСТУВАННЯ ТА ЗВІТНІСТЬ

- Після кожного виправлення багу розробником Agent 5 зобов'язаний провести регресійний тест — перевірити не лише виправлену проблему, але й суміжний функціонал.
- Усі знайдені дефекти фіксуються в `docs/qa/BUG_REPORT.md` із зазначенням:
  * ID дефекту (наприклад, `BUG-015`)
  * Пріоритет (P0–P3)
  * Покрокова інструкція для відтворення
  * Фактичний vs Очікуваний результат
  * Статус (`Open` -> `In Progress` -> `Fixed` -> `Verified` -> `Closed`)
