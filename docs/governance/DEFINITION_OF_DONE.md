# Definition of Done — коли щось можна назвати «готовим»

Цей документ важливіший за будь-який звіт. Якщо доказу немає, статус не підвищується.

## Рівні доказів

| Рівень | Назва | Що має бути | Хто збирає |
|---|---|---|---|
| **L0** | Написано | Зміни є в гілці / PR | Виконавець |
| **L1** | Збирається | Посилання на **зелений** запуск CI для цього коміту | Виконавець (`gh run view`) |
| **L2** | Протестовано автоматично | Автотести EditMode, що покривають зміну, зелені в CI; назви тестів у звіті | Виконавець, перевіряє Агент 5 |
| **L3** | Працює на телефоні | APK з цього коміту встановлено через `adb`; скриншоти або запис екрана; витяг `adb logcat` без помилок `Exception` / `FATAL` | Агент 5 (або Агент 4) |
| **L4** | Перевірено людиною | Власник або тестувальник зіграв і відповів на чекліст | Власник / тестувальники |

## Яких рівнів вимагає кожен тип зміни

| Тип зміни | Мінімум для статусу «QA Verified» |
|---|---|
| Документи, конфіги без впливу на гру | L0 + перевірка Агентом 5 |
| Логіка гри, економіка, збереження | L2 |
| Інтерфейс, ввід, звук, анімації | L3 |
| Реклама, згода, покупки, аналітика | L3 на реальному телефоні з тестовими ID |
| Закриття етапу | L3 для всіх змін етапу + L4 для воріт етапу |
| Публікація | L4 + рішення Власника |

## Заборонені формулювання без доказу
«100% готово», «бездоганно», «перевірено», «PASS», «нуль помилок», «стабільні 60 FPS» — лише з посиланням на доказ відповідного рівня.
Якщо перевірка не проводилась, пишемо дослівно: **«НЕ ПЕРЕВІРЕНО: <причина>»**.

## Де зберігаються докази
- `docs/qa/evidence/<TASK-ID>/` — скриншоти, витяги logcat (обрізані до суті), посилання на CI.
- `docs/qa/TEST_RESULTS.md` — таблиця: тест → рівень → дата → коміт → посилання на доказ.
- Ніяких секретів, рекламних ID чи персональних даних у доказах.
