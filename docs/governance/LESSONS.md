## Unity 6.3 / game-ci / збірка в CI (E0-03, 2026-11-10)
- **Ліцензія Unity не прив'язана до версії.** Секрет `UNITY_LICENSE` (.ulf, Personal), отриманий для 2022.3, активує 6000.3 без жодних дій. Повторна активація при зміні версії Unity не потрібна (game.ci/docs/github/activation).
- **Unity 6.3 не підтримує Android API 24.** Мінімум — API 25 (перелік `AndroidSdkVersions` починається з `AndroidApiLevel25`). Перед рішенням про min API звіряйся з вимогами конкретної версії Unity.
- **Файли редактора генерує лише CI.** Локального Unity 6.3 немає: `.meta`, `ProjectSettings/*.asset`, `packages-lock.json`, ресурси URP отримуємо тимчасовим кроком `upload-artifact` → `gh run download` → коміт. Новий скрипт чи папка без `.meta` → крок CI «Verify Project Files Are Committed» впаде і покаже, яких файлів бракує.
- **🔴 Не вивантажуй `ProjectSettings.asset` артефактом після збірки з підписом.** Unity записує в нього псевдонім ключа (секрет `ANDROID_KEYALIAS_NAME`) і шлях до keystore. Репозиторій публічний, артефакти доступні стороннім. `BuildScript` очищає ці поля після збірки (`ProjectSetup.ClearAndroidSigning`), але в разі аварії редактора вони можуть лишитися — перед вивантаженням завжди перевіряй/очищай.
- **Перше вмикання Input System ламає збірку в тому ж сеансі редактора:** `script class layout is incompatible between the editor and the player`. Причина — редактор ще скомпільований зі старим вводом. `activeInputHandler: 1` має бути вже закомічено в `ProjectSettings.asset` до запуску збірки. Те саме стосується будь-яких налаштувань, що змінюють компіляційні символи.
- **URP створює файли в корені `Assets`** (`UniversalRenderPipelineGlobalSettings.asset`, `DefaultVolumeProfile.asset`) — `ProjectSetup` переносить їх у `Assets/_Project/Settings`. Пакет `com.unity.test-framework.performance` (транзитивна залежність URP) під час збірки створює `Assets/Resources/PerformanceTestRun*.json` — вони в `.gitignore`, не комітити.
- **game-ci копіює свої скрипти в `Assets/Editor/…/UnityBuilderAction`** під час збірки — це не файли проєкту, не комітити.
- **Запуск воркфлоу з гілки** (`gh workflow run <файл> --ref <гілка>`) бере YAML із гілки. Помилка `Workflow does not have 'workflow_dispatch' trigger` означає зіпсований YAML у гілці (у нас — керівний символ `\x01`, що потрапив замість `\1` при генерації файлу скриптом). Після скриптових правок перевіряй файл на керівні символи.
- **Кеш `Library` зберігається лише після успішного завдання CI.** Поки запуск не зелений, кожна збірка IL2CPP — повна (≈20 хв); після — швидше.
- **Порожні значення в YAML Unity мають пробіл після двокрапки** (`AndroidKeystoreName: `). Ручне редагування без пробілу дає різницю з тим, що пише редактор.
- **Образ `unityci/editor:ubuntu-6000.3.28f1-android-3` збирає під target API 36** (`compileSdkVersion 36` у готовому APK); Gradle 9.3.1, AGP 9.1.1. Фактичні min/target API дивись у кроці CI «Print APK Info», а не лише в налаштуваннях.
- **Не роби висновків з обрізаного виводу.** Список папок SDK, обрізаний `head`, показав лише платформи 34/35/37.0 — і дав хибний висновок «платформи 36 немає». Перевіряй факт прямим способом (тут — `aapt2 dump badging` готового APK).
- **Кеш `Library` у CI — не лише прискорювач, а й потенційне сховище даних підпису** (QA E0-03, припущення, НЕ ПЕРЕВІРЕНО): Unity генерує Gradle-проєкт у `Library/Bee/Android/…`, куди при власному keystore може записати конфігурацію підпису. Кеші `main` можуть відновлювати воркфлоу PR із форків. Перевіряй вміст кешу лише за іменами файлів (`grep -rl`), без виводу значень; Gradle-проєкт краще виключати з кешу.
- **Перевіряй секрети в журналах класифікацією, а не виводом:** рахуй «замасковано `***`» / «інше, довжина N», щоб навіть під час перевірки значення не потрапило в чат чи звіт.

## CI: тести, кеш і підпис (E0-04, 2026-11-10)
- **Кеш `Library` містив паролі підпису (підтверджено).** Збірка з власним ключем пише пароль сховища/ключа і псевдонім у `Library/Bee/Android/Prj/IL2CPP/Gradle/launcher/build.gradle`, `Library/Bee/artifacts/Android/Gradle/launcher/build.gradle(.xml)`, `Library/Bee/Player*-inputdata.json`, `Player*.dag(.payloads)`, `tundra.log.json`, `csharpactions/IntermediateFiles.txt_*.info`, Gradle `executionHistory.bin`, `Library/SourceAssetDB`. Виправлення: після збірки видалити файли зі збігами (скрипт `.github/workflows/scripts/scan-signing-data.sh report`) і лише тоді зберігати кеш; видалення цих файлів збірку не ламає і мало її сповільнює. Збірки PR підписуються debug-ключем.
- **Редактор Unity на Linux (test-runner) дописує в `Packages/manifest.json` і `packages-lock.json`** sysroot-пакети `com.unity.sdk.linux-*`, `com.unity.toolchain.linux-x86_64-linux` 1.1.1. Це не зміна проєкту: у job тестів Packages з перевірки «файли закомічені» виключено.
- **Скан кешу `grep -rlF -f файл` з виводом лише імен файлів** безпечний для публічного журналу; лише не рахуй у pipe-підоболонці (змінні не повертаються — використовуй `< <(...)`).
- **`concurrency` із `cancel-in-progress` лише для `pull_request`:** push у PR скасовує застарілий запуск; запуск, який скасували, має висновок `cancelled`, а не `failure` — для доказу «червоний CI» дай запуску завершитись.
- **Windows/Git Bash:** `git add` пише попередження про LF→CRLF — це нормально; значення .meta для вручну створених файлів можна писати самому (`fileFormatVersion: 2` + `guid`), CI-перевірка підтвердила, що Unity нічого не змінює.
- **`actions/cache@v4` зберігає кеш у post-кроці з `post-if: success()`** (QA E0-04, перевірено в `action.yml` і журналах): кроки очищення/запобіжника з `always()` перед кінцем job гарантовано виконуються раніше за збереження, а впалий job кеш не зберігає («Post Cache Library: skipped»).
- **`unity-test-runner` без `customImage` бере образ `…-linux-il2cpp-3`**, і саме він дописує sysroot-пакети в `Packages/manifest.json`; образ `…-android-3` (теж Linux) — ні. Причину шукай в образі, а не «в Linux» (BUG-013).
- **`paths-ignore` для `pull_request` рахується за всім диффом PR**, а не за останнім комітом: коміт лише з документами в PR із кодом теж запускає CI (зручно для доказу на голові PR).
- **JAR-підпис AAB розкриває псевдонім ключа:** файли `META-INF/<перші 8 символів псевдоніма>.SF/.RSA`. Публічний артефакт з AAB = публічний префікс псевдоніма (BUG-015). Перевіряючи, не записуй сам префікс.

## Core / детермінізм / тести без локального Unity (E0-06, 2026-11-10)
- **Локально немає ні `dotnet`, ні Roslyn** (лише `csc` .NET Framework із C# 5 — сучасний код не компілює). Компіляція C# — тільки в CI. Щоб не витрачати запуски: арифметику і «золоті» значення перевіряй незалежною реалізацією в Node.js (`BigInt` для 64-бітних цілих; `double` у JS той самий IEEE 754). Увага: `Math.round` у JS округлює половинки вгору, а `Math.Round` у C# — до парного; для порівняння напиши округлення до парного сам.
- **Накопичувач часу в `double` залежить від нарізки кадрів:** 600 × (1/60) дає 10,000000000000076, а не 10 — біля межі такту кількість тактів залежить від того, як час порізано на кадри. Правильно: кожен кадр одразу переводити в цілі частки такту (у нас 1e-6 такту) і накопичувати ціле число; порівняння з межею наздоганяння теж робити в цілих.
- **«Золотий» тест має сенс лише з незалежним джерелом значень.** Значення, зняті з власного коду, фіксують і його помилки. Для SplitMix64 еталон: seed 0 → `0xE220A8397B1DCDAF`, seed 1234567 → `6457827717110365317`.
- **Поля, створені компілятором, — статичні й змінні** (кеш делегатів `<>9__…`). Тест «немає змінного статичного стану» через рефлексію має пропускати імена, що починаються з `<`.
- **Heredoc у Bash-інструменті ламається на апострофах в українському тексті** (`об'єкт`) навіть із `<<'EOF'` — файли з таким текстом створюй інструментом запису файлів або через Node.

## Збереження / тести без локального компілятора (E0-07, 2026-11-11)
- **`File.Move` із перезаписом і `File.Replace` — не основа атомарного запису.** У профілі .NET Standard 2.1 (Unity 6.3) перевантаження `File.Move(src, dst, overwrite)` немає, а `File.Replace` поводиться по-різному на платформах. Правильно: порядок, де кожне перейменування йде на вільне ім'я (стару резервну копію видалити → основний у резервний → тимчасовий в основний), а завантаження вміє стан «є лише резервна копія».
- **Атомарність доводиться перебором точок збою, а не одним тестом.** Обгортка сховища, яка «вбиває процес» на операції N (ця й усі наступні кидають `IOException`), і цикл за всіма N; після кожного збою завантаження має дати попередній або новий стан. Кількість операцій бери з контрольного запуску без збою, щоб цикл не застарів.
- **Параметризований клас тестів `[TestFixture(false)] [TestFixture(true)]`** працює в Unity Test Framework: один набір сценаріїв іде і на сховищі в пам'яті, і на справжніх файлах; у звіті класи називаються `Ім'я(False)` / `Ім'я(True)`, тести рахуються двічі.
- **Не передавай у `[TestCase]`/`TestCaseSource` рядки з керівними символами чи довгим JSON** — аргумент стає частиною назви тесту у файлі результатів XML і в журналі CI. Передавай коротку назву випадку, а текст бери з таблиці в тесті.
- **`node -e` і heredoc у Bash-інструменті можуть перетворити `\u0000` на справжній керівний символ у файлі.** Після скриптових правок перевіряй: `grep -c -a -P '[\x00-\x08\x0b\x0c\x0e-\x1f]' файл` має дати 0.
- **`StringBuilder.Append(long)` і `long.ToString()` беруть поточну культуру** (знак мінуса в деяких культурах інший). У форматах даних — лише `ToString(CultureInfo.InvariantCulture)` і `TryParse(..., CultureInfo.InvariantCulture, ...)`.

## QA збереження (E0-07, 2026-11-11, Агент 5)
- **Модель збою для збережень має включати збої ЧИТАННЯ, а не лише «процес загинув під час запису».** `catch (Exception)` навколо читання файла плутає «файл тимчасово недоступний» (`IOException`, `UnauthorizedAccessException`) з «файл пошкоджений» і веде до карантину справних даних та хибного скидання (BUG-019). Обгортка сховища зі збоєм має вміти кидати виняток у `ReadText` під час `Load`.
- **NUL у текстовому файлі + `core.autocrlf=true` = CRLF в історії.** Git вважає файл із нульовим байтом двійковим і не нормалізує кінці рядків під час коміту; diff у PR показує «Binary file». Перед комітом документів перевіряй: жодного байта менше 0x20, крім табуляції й переходу рядка (BUG-021).
- **Атомарний запис зручно доводити поза Unity:** невелика модель на Node.js (порт семантики сховища в пам'яті) перебирає всі початкові стани файлів x кожну точку збою за секунди; див. `docs/qa/evidence/E0-07/independent_save_model.js`.

## UI Toolkit у headless-збірці (E0-05, 2026-11-11)
- **`ScriptableObject.CreateInstance<PanelSettings>()` + `CreateAsset` змушує Unity створити `Assets/UI Toolkit/UnityThemes/UnityDefaultRuntimeTheme.tss` (+.meta) у корені Assets.** Крок CI «Verify Project Files Are Committed» бачить це як нові файли. Рішення в E0-05: сцени й PanelSettings генеруються перед збіркою, після збірки `SceneSetup.Cleanup()` видаляє їх, а шляхи додано в `.gitignore`.
- **Сцени в APK (Unity 6, Android, IL2CPP) лежать як `assets/bin/Data/level0..N`;** BuildScript рахує їх у готовому APK (`System.IO.Compression.ZipFile` працює в Editor-збірці).
- **Оновлення (E0-14, 2026-11-11):** два уроки вище про sysroot-пакети й виключення `Packages` для job тестів застаріли: job тестів тепер на `customImage: unityci/editor:ubuntu-<версія>-android-3` (той самий образ, що й збірка), `Packages` у перевірці файлів повернено. Сторонні `uses:` закріплені SHA коміту з коментарем версії (оновлюючи версію — міняй SHA через `gh api repos/<owner>/<repo>/git/ref/tags/<tag>`).

## Перевірка на телефоні (E0-12, 2026-11-11, Агент 5)
- **Зелений CI і сотні тестів EditMode не доводять, що UI видно на телефоні.** E0-05/E0-08 мали L1–L2, а APK показав порожній екран (BUG-029). Для UI потрібен L3 до злиття або smoke-перевірка, що на екрані є хоч одна видима кнопка.
- **Однаковий колір камери і фону UI маскує збій рендеру.** Одноколірний скриншот не відрізняє «панель не малюється» від «панель порожня». Для діагностики фон контейнера має відрізнятися від кольору камери.
- **Код гри без логів = сліпа діагностика на пристрої.** Мінімальний лог переходів сцен у Release (без особистих даних) потрібен з першого каркаса (BUG-030).
- **Git Bash: `MSYS_NO_PATHCONV=1` ламає `cmd //c`** (запускається порожній cmd, файл не створюється). У Git Bash `adb exec-out screencap -p > файл.png` працює бінарно коректно; пастка з `>` стосується лише PowerShell. Перевіряй `file *.png` після знімання.
- **Скриншот може містити особисті дані з системних сповіщень** (напр. назва ПК у тості буфера обміну). Перед комітом доказів переглядай кожен кадр.

## QA ланцюгових PR (S1-09a, 2026-11-13, Агент 5)
- PR із базою не `main` не має перевірок (`gh pr checks` → «no checks reported»): CI запускають вручну `workflow_dispatch`. Доказ — `gh run view <id> --json headSha,event,conclusion` і звірка `headSha` з останнім комітом із кодом (`git diff --stat <sha> HEAD` — лише docs).
- «Тестів не менше, ніж на базі» перевіряй не числом, а списком: витягни `fullname` з `editmode-results.xml` бази і PR (`gh run download -n KebabStreet-EditMode-TestResults`), `comm -23 base pr` має бути порожнім.

## QA вигляду UI Toolkit без телефону (S1-09b, 2026-11-13, Агент 5)
- Логічна ширина панелі `ScaleWithScreenSize` 1080x1920, match 0.5 на телефоні шириною 1080 = 1080 / √(H/1920): 1080x2340 → ≈ 978, 1080x2400 → ≈ 966 (не 1080!). Для рядів з `flexWrap` рахуй суму `width + margin` елементів проти цієї ширини мінус поля і рамки зон — так переповнення видно ще на L0, до скриншота.

## QA бот-тестів «через UI» (S1-09c, 2026-11-13, Агент 5)
- «Бот грає лише через UI» перевіряй у двох напрямках: (1) **дії** — лише ті методи, які викликають лямбди кнопок (grep прямих команд Core у боті); (2) **знання** — що бот читає: дозволено все, що видно на екрані (дошка, черга, значки, терпіння %), заборонено seed, розклад хвиль, точні мс. Точний збіг результату з ботом симуляції на тому ж seed — сильний доказ, що шар тапів нічого не губить.
- `gh run download -D <тека>` падає «file exists», якщо в теці вже є файл з артефакту — завжди нова порожня тека.

## Ручні .meta для PNG (S1-12, 2026-11-13, Агент 5)
- Ручно написані `.meta` для PNG-спрайтів не проходять крок CI «Verify Project Files Are Committed»: Unity сам дописує спрайт-секції (`internalIDToNameTable`, `sprites`, `spriteID`, platformSettings Standalone/Android). Для нових PNG бери справжні `.meta` з CI (тимчасовий `upload-artifact`), а не пиши вручну; тимчасовий крок потім прибери й перевір `git diff -- .github` проти бази.
- Тест «усі файли ресурсів у реєстрі» перевіряй на те, які теки він реально сканує (`Directory.GetFiles` без рекурсії, одна тека).
- Скретчпад QA не чистий між сесіями: для `gh run download` завжди створюй нову тека з унікальною назвою, інакше порівняєш не ті файли.

## Нові файли = нові .meta (S1-13, 2026-11-13, Агент 2)
- Кожен новий `.cs` (і тестовий теж) потребує `.cs.meta` (`fileFormatVersion: 2` + `guid: <32 hex>`), інакше крок CI «Verify Project Files Are Committed» падає. Перед пушем: `git status` і перевір, що для кожного нового файлу в `Assets/` є пара `.meta`.
- Ручні `.meta` для WAV (AudioImporter, serializedVersion 8, loadType 0, compressionFormat 1, quality 1, normalize 1) і для теки ресурсів Unity 6000.3 лишив без змін; для PNG-спрайтів це не так (див. урок вище).

## Спільне робоче дерево і ланцюгові PR (Агент 0, 2026-11-13)
- Агенти й Агент 0 працюють в ОДНІЙ папці репозиторію. Агент 0 не перемикає гілку (`git checkout`) і не робить `git add -A`, поки працює субагент: чужі незакомічені правки потрапляють у чужий коміт (так сталось з рівнями L01–L05 при записі рішень Власника; відновлено без втрат).
- Документи, які Агент 0 пише під час роботи агента, коміти точково (`git commit -- <шляхи>`) і лише на тій самій гілці.
- Ланцюгові PR (база — не `main`) не запускають CI самі: `gh workflow run build-android.yml --ref <гілка>`, статус — одноразові `gh run view` (довгий `gh run watch` вбивається системою через пам'ять).
- Не вставляй у одну команду bash довгі heredoc з апострофами/`sed` — синтаксична помилка обриває всю команду (документи лишаються не оновленими, а гілка вже створена). Довгі файли пиши інструментом Write.
- Фінальний звіт субагента може не дійти: перевір гілку/CI/журнал картки самостійно.
