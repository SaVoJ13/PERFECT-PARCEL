# Як дати друзям пограти в тестову збірку (без Google Play) — ЧЕРНЕТКА

Статус: чернетка для Власника. Нічого з цього не виконано і не налаштовано. Рішення — питання №31 в `docs/governance/OWNER_INBOX.md`.
Мета — щоб 3–5 знайомих спробували гру (ворота Етапу 1, `docs/product/ROADMAP.md`).

## Спільні правила безпеки (діють для всіх варіантів)
- **Підпис.** Збірка CI зараз підписана ключем-кандидатом, який **вважається скомпрометованим** (`OWNER_INBOX` №10: файл ключа в публічній історії git, паролі були в кешах CI). Тому ця збірка — **лише тестова, не «релізна»**. Не називайте її релізом, не завантажуйте в Google Play. Для Google Play буде створено новий ключ.
- Не поширювати APK публічно (пости, відкриті канали). Лише знайомим, особисто.
- Тестова збірка не містить реальної реклами й покупок (заглушки), не збирає особистих даних.
- Телефони друзів: просимо вимкнути «невідомі джерела» назад після встановлення.
- Збірка підписана іншим ключем, ніж майбутня релізна: перед релізом тестову гру треба **видалити** і поставити нову; прогрес пробної гри пропаде (це нормально).
- Контрольна сума sha256 файлу вказується поруч із посиланням — щоб друг міг переконатися, що файл не підмінено (не обов'язково для друга).

## Варіант А. Прямий файл APK через месенджер або хмару

**Суть:** Власник надсилає друзям файл `KebabStreet.apk` особисто.

**Кроки для друга (простими словами):**
1. Отримайте файл `KebabStreet.apk` від Власника (у месенджері натисніть «Завантажити»). Файл близько 33 МБ.
2. Відкрийте його (застосунок «Мої файли» → «Завантаження» → торкніться файлу).
3. Телефон скаже, що установлення з цього джерела заборонене. Натисніть «Налаштування» і увімкніть «Дозволити з цього джерела» для цього застосунку (месенджера чи «Мої файли»).
4. **Samsung Auto Blocker:** якщо установлення блокує Auto Blocker — Налаштування → Безпека та конфіденційність → Auto Blocker → вимкніть. Після гри можна ввімкнути назад.
5. Якщо з'являється «Google Play Protect»: виберіть «Встановити все одно» (гра наша, не з магазину).
6. Натисніть «Встановити», відкрийте гру. Грайте, потім дайте відповіді на анкету.
7. Після гри видаліть застосунок (довго тримати іконку → «Видалити») і вимкніть дозвіл «невідомі джерела».

**Кроки для Власника:**
1. Агент 0 запускає збірку CI (`gh workflow run build-android.yml`) і повідомляє, де артефакт.
2. Власник завантажує артефакт `KebabStreet-Android-Builds` (потрібен вхід у GitHub), розпаковує, бере `KebabStreet.apk` (тека `..._BurstDebugInformation_DoNotShip` — ігнорувати і **не надсилати**).
3. Власник надсилає файл знайомим особисто (месенджер) + sha256 (його надає Агент 0).
4. Спостерігає за грою, заповнює `PLAYTEST_FORM.md`.

**Ризики:** Play Protect може лякати («невідомий розробник») — друг має знати, що так буде; пересилання APK через сторонні сервіси — ризик підміни; ключ скомпрометований (див. вище). Файл в месенджері може бути стиснутий або перейменований.
**Дії в акаунтах Власника:** лише завантаження артефакту зі свого GitHub (вхід в акаунт Власника). Нових акаунтів/витрат немає. Надсилання друзям — повідомлення від імені Власника, робить сам Власник (3.2).
**Плюси:** найпростіше, безкоштовно, без нових акаунтів, працює вже зараз. **Мінуси:** друг долає кілька екранів попереджень; важко оновлювати збірку (треба знову надсилати файл).

## Варіант Б. Firebase App Distribution

**Суть:** Власник завантажує APK у Firebase; друзі отримують лист із запрошенням і ставлять через застосунок-тестувальник.

**Кроки для друга:**
1. Надіслати Власнику e-mail свого Google-акаунта (потрібен, щоб отримати запрошення) — це персональні дані, зберігаються лише для запрошень, в анкету не потрапляють.
2. Відкрити лист-запрошення на телефоні, прийняти.
3. Встановити застосунок Firebase App Tester / відкрити веб-сторінку тестувальника, обрати збірку, натиснути «Завантажити».
4. Далі як у варіанті А (невідомі джерела, Play Protect, Auto Blocker — дозволи теж потрібні).
5. Грати, відповісти на анкету.

**Кроки для Власника:**
1. Створити проєкт Firebase в акаунті Власника і зареєструвати Android-застосунок — **дія в акаунті, лише Власник (3.2)**.
2. Додати тестувальників за їхніми email.
3. Завантажити APK (вручну в консолі або автоматично з CI: потрібен секрет у GitHub Settings → теж лише Власник).
4. Підтвердити, що вибір Firebase узгоджується з правилами про залежності/дані: Firebase — окремий сервіс; для гри SDK не потрібен, App Distribution працює без нього в коді (припущення, не перевірено; перед використанням перевірити за офіційною документацією Firebase).

**Ризики:** збір email друзів; потрібен акаунт Google у друзів; хмарний сервіс Google з правилами використання; ключ той самий, скомпрометований.
**Дії в акаунтах Власника:** створення проєкту Firebase, додавання тестувальників, за автоматизації — секрет GitHub. Усе — 3.2.
**Плюси:** зручне оновлення, чітка кількість тестувальників, є статистика встановлень. **Мінуси:** складніше для друзів, потрібні email і акаунти, налаштування Власником.

## Варіант В. Google Play, внутрішнє тестування

**Суть:** збірка завантажується в Google Play Console як «внутрішнє тестування»; друзі ставлять з Google Play за запрошенням.

**Кроки для друга:**
1. Надіслати Власнику e-mail Google-акаунта (як у Б).
2. Відкрити посилання-запрошення від Власника, натиснути «Стати тестувальником».
3. Встановити гру з Google Play, як звичайну. Невідомі джерела, Auto Blocker і Play Protect — не потрібні.
4. Грати, відповісти на анкету.

**Кроки для Власника:**
1. Мати акаунт розробника Google Play Console (оплату і реєстрацію перевірити за офіційним джерелом; не робилось).
2. Створити застосунок у Console, список тестувальників (email), завантажити AAB.
3. **Обов'язково:** спершу замінити скомпрометований ключ підпису (`OWNER_INBOX` №10) — інакше завантажувати в Google Play не можна.
4. Опублікувати у внутрішньому треку; це єдиний трек, який дозволений без окремого рішення Власника (3.2 «будь-який трек, крім внутрішнього тестування»), але **усі дії в Console все одно виконує Власник**.

**Ризики:** потрібен готовий ключ підпису, налаштований Console, анкети Google; помилки в Console блокують реліз; email друзів.
**Дії в акаунтах Власника:** Play Console (акаунт, застосунок, тестувальники, завантаження), заміна ключа. Усе — 3.2.
**Плюси:** найбільш «справжній» шлях, найпростіше для друзів, оновлення автоматичні, відпрацьовується реліз-процес. **Мінуси:** найбільше підготовки, залежить від заміни ключа, оплата/реєстрація акаунта розробника (3.2), для Етапу 1 це може бути зарано.
