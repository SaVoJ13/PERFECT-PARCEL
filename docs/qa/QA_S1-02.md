## 4. Аналіз коду (ризикові місця)
- `ShiftSimulation.Tick`: `RunActions()` винесено з-під `if (Grill != null)`. Для зміни з грилем порядок той самий (`Grill.Advance` → дії). Для зміни без гриля дії гриля в чергу не потрапляють (`Enqueue` вимагає `Grill != null`), тож гілка `default → Grill.ActionTicks` у `ActionTicksOf` не отримає `null`. Старі тести без гриля зелені.
- `TakeMeat` з дошкою: на повну дошку повертає `BoardFull` раніше, ніж дивиться на стан м'яса (тобто й для сирого/порожнього слота). Гриль при цьому не змінюється — нешкідливо, лише пріоритет коду результату.
- `Board.CheckRecipe`: спершу «зайвий/дублікат», далі порядок і пропущені кроки; optional до завершення кроків — `WrongOrder` (додаванням не виправити). Маска optional обмежена `MaxRecipeLength = 16` — переповнення `1 << n` неможливе.
- Ціна: до 16 × `MaxCoins` (1 000 000) — в межах `int`.
- Зовні `Board` лише для читання (мутатори `internal`, сетери `private`); `BoardSnapshot` копіює масив (тест `BoardSnapshot_CopiesItsArray…`).
- `ShiftConfig.GetErrors` перевіряє дошку разом із грилем; `ShiftSimulation` з невалідним конфігом кидає виняток із причиною (`ShiftSimulation_RejectsInvalidBoardConfig…`). Старі конструктори збережено (`OldConstructors_GiveShiftWithoutBoard`).
