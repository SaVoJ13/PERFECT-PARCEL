## 3. BUG-025 — Verified Fixed
Код: `Load` запам'ятовує `_blockedBy` (Unavailable/NewerVersion), будь-який інший результат його скидає; `Save` на початку відмовляє без звернення до носія. Тест `Save_AfterUnavailableLoadEvenIfAccessReturned…` відтворює кроки BUG-025 (250/100 → нечитабельні → Unavailable → доступ повернувся → два `Save` → файли побайтово ті самі, прогрес 250 цілий; потім `Load` → Primary, `Save` = Saved). `Save_AfterNewerVersionLoad…` — відмова, потім `Load` знову вмикає запис. Тест реально ловить помилку (до виправлення було Saved/Saved).

Спроби обійти (аналіз коду, окремий Node-запуск не робився, бо логіка проста і покрита тестами):
- Unavailable -> доступ відновився -> `Save`: відхилено. OK.
- Unavailable -> повторний `Load` лишається Unavailable -> блок зберігається. OK.
- NewerVersion основного або `.bak`: основний — блок у `Load`; `.bak` новіший при справному основному — `Source=Primary`, але `Save` сам перевіряє файли й дає `RejectedNewerSave`. OK.
- Backup Unavailable при непридатному основному — Unavailable, блок. OK.
- `Load` не кидає винятків назовні (`Inspect` ловить усе, карантин ловить IO), тож `_blockedBy` не лишається застарілим.

## 4. BUG-026 — Verified Fixed
`Load` при справному основному й пошкодженому `.bak`: `CorruptFilesFound=1`, `.bak` перейменовано в `.corrupt`, дані й `CanSave` правильні (тест `Load_ValidPrimaryAndCorruptBackup…`). `Save` без попереднього `Load` відкладає пошкоджений `.bak` замість `DeleteIfExists` (тест `Save_…WithoutLoad_QuarantinesInsteadOfDeleting`: вміст у `.corrupt`, `.bak` = попередній основний, нові дані завантажуються). Побічний ефект: `Load` тепер перейменовує файл (раніше це робилось і для основного/резервного в інших гілках; документований коментар «нічого не записує» трохи неточний — P3).

## 5. Залишковий ризик (P3, не блокує, окремого BUG не заведено, передано Агенту 0)
Запобіжник живе в екземплярі `SaveService`. Новий екземпляр без `Load` має `_blockedBy = null`, тож `Save` не відмовить, якщо до того файли були нечитабельні, а зараз читаються (внутрішні перевірки `Save` ловять лише поточну нечитабельність). У штатному потоці гра завжди викликає `Load` на старті, тому ризик теоретичний; для E0-05 потрібно: один екземпляр на гру, `Load` до першого `Save`, при Unavailable/NewerVersion не зберігати чистий профіль (контракт описано в журналі картки).
