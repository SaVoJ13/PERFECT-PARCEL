## 4. Аналіз коду (вибірково, ризикові місця)
- Порядок такту: `ElapsedTicks++` → `Grill.Advance()` → `RunActions()` → кінець зміни. Наслідки: зняти можна на такті готовності, на такті пригорання — ні (`MeatBurnt`), викинути на такті пригорання — можна. Узгоджено з тестами `Take_OnTickWhenMeatBecomesDone_Succeeds`, `Take_OnTickWhenMeatBurns_IsIgnored`, `Discard_OnTickWhenMeatBurns_Succeeds`.
- Пауза: `Tick()` поза `Running` повертає false до будь-яких змін — таймери гриля і поступ дії стоять (GAME_DESIGN розд. 1, 4: «Пауза заморожує всі таймери гриля»). Тести `Pause_FreezesGrillTimers…`, `Pause_FreezesActionInProgress`.
- `RunActions`: за такт — щонайбільше один такт роботи; дії з тривалістю 0 виконуються всі в одному такті; простій не накопичується (`IdleTime_IsNotBanked…`). Нескінченного циклу немає: кожна ітерація або повертає, або видаляє дію.
- Округлення мс → такти монотонне, тому `warnMs ≤ burnMs` гарантує `warnTicks ≤ burnTicks`.
- Зовні `Grill`/`GrillSlot` лише для читання (мутатори `internal`, сетери `private`).
