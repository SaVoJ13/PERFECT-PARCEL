## Мета
Збірка запускається на телефоні й проходить шлях: bootstrap → екран завантаження (збереження) → головне меню → порожня сцена зміни (таймер із `ShiftSimulation` іде, кнопка виходу в меню). Це основа для всього Етапу 1.

## Вхідні дані
- `docs/architecture/ARCHITECTURE.md` (збірки, композиція в `Game`), `ADR-018` (UI Toolkit), `AGENTS.md` розд. 5 (headless-first, тексти лише ключами, логіка окремо від Unity).
- `Assets/_Project/Core/**` (`ShiftSimulation`, `ShiftConfig`), `Services/Save/**` (контракт `Load`/`Save`, `CanSave`, `SaveWriteResult`, `ProgressReset`, `NewerVersion`, `Unavailable`), `Editor/BuildScript.cs`, `Editor/ProjectSetup.cs`.
- Журнал `docs/tasks/E0-15.md` — нова поведінка `Save` для UI; `docs/governance/LESSONS.md`.

## Що зробити
1. Bootstrap (композиція в `KebabStreet.Game`): створює `SaveService`, годинник, `ShiftSimulation`; один екземпляр `SaveService`, `Load` завжди до першого `Save`.
2. Сцени створюються **Editor-скриптом** (headless, у CI), без ручних дій у редакторі: Boot, Menu, Shift; додаються в Build Settings. Інтеграція зі збіркою — мінімальна зміна `BuildScript`/`ProjectSetup` лише якщо необхідно (опиши в журналі).
3. UI на UI Toolkit (UXML/USS мінімальні, плейсхолдери): меню — «Грати» і «Налаштування» (заглушка), зміна — таймер і «Вийти». Дозволено мінімальні UXML/USS у `Assets/_Project/UI/` як виняток Агента 0 (стиль потім за Агентом 2).
4. Обробка станів збереження в UI: `ProgressReset` (повідомлення), `NewerVersion` ("оновіть гру", запис заборонено), `Unavailable`, відмови `Save` (`RejectedAfterUnavailableLoad`, `RejectedNewerSave`) — без збереження чистого профілю.
5. Тексти лише через ключі. Локалізація — E0-08; тут тонкий інтерфейс пошуку ключа з тимчасовими EN-рядками.
6. Тести EditMode на логіку контролерів/стану переходів, що не потребує Unity-сцен (логіка bootstrap/переходів — окремі класи без `MonoBehaviour`).
7. CI збирає APK зі сценами; перевірити в збірці, що сцени справді потрапили (Build Settings / вивід збірки).
