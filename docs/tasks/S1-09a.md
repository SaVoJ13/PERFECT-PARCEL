## Мета
Частина екрана зміни, у яку можна грати: UI Toolkit (D-03), портретна орієнтація, керування тапами, **поверх готового `KebabStreet.Core` через `ShiftDriver` (S1-08), без дублювання логіки в UI**. Усі видимі тексти — ключі локалізації EN/UK/PL.

## Вхідні дані
`docs/design/GAME_DESIGN.md` (розд. 2–6, 9), `LEVEL_DESIGN.md`, `docs/design/ART_STYLE_GUIDE.md`, `docs/design/PROVISIONAL_RULES.md`, `Game/Flow/ShiftDriver.cs`, `Game/Views/ShiftController.cs`, `UiFactory.cs`, `Core/Shift/ShiftSnapshot.cs` (знімки гриля, черги дій, дошки, клієнтів).

## Що зробити
- Каркас екрана зміни (портрет): верхня смуга з таймером, ціллю рівня, монетами, кнопка паузи; зони для прилавка (S1-09b) і збирання (S1-09c) — порожні контейнери.
- Гриль: слоти за конфігом, у кожному стан м'яса (порожньо / сире / готується / готове / пригоріле) з індикатором прогресу; тап — покласти м'ясо, зняти готове, викинути пригоріле (за GAME_DESIGN розд. 4, PROVISIONAL_RULES 13/15).
- Підказка «Ціль виконано! Ще встигнеш на ★★» (ключ вже є) і плашка паузи.

## Файли, які можна змінювати
`Assets/_Project/Game/Views/**`, `Game/Flow/**`, `Assets/_Project/UI/**` (UXML/USS, тимчасово — зона Агента 2, Керівник дозволяє для цього завдання), `Resources/Localization/**` (лише нові ключі), `Tests/**`, журнал картки. Правила Core не змінювати; якщо знімку бракує даних для показу — мінімальне доповнення знімка допустиме з тестом, запиши в журнал.

## Критерії приймання (перевірювані)
- [ ] Тест: для кожного стану слота модель вигляду дає очікуваний показ (5 станів).
- [ ] Тап по слоту викликає правильну `ShiftTap` для кожного стану.
- [ ] Каркас показує таймер, ціль і монети зі знімка/драйвера.
- [ ] Автотест: контролер/модель вигляду без Unity-об'єктів, де можливо (стан знімка → дані для показу), і тест «усі ключі є в усіх мовах» зелений.
- [ ] Тапи йдуть лише в `ShiftDriver.Tap`; жодної ігрової логіки в `Views`.
- [ ] CI зелений для останнього коміту; тестів не менше, ніж на базі; жодного вимкненого.
