## Ризики / на що звернути увагу
- **Ліцензія Unity** (`OWNER_INBOX` №5): секрет `UNITY_LICENSE` отримано для 2022.3; чи прийме його образ 6.3 — НЕ ПЕРЕВІРЕНО. Перевір першим дешевим запуском CI (ще до всієї роботи). Якщо активація не проходить — **не обходь**: запиши точний текст помилки в журнал, підготуй для Агента 0 інструкцію `/owner-step` (що саме має зробити Власник) і продовжуй усе, що можна зробити без CI; статус у звіті — `Blocked`.
- Секрети GitHub і налаштування репозиторію ти не змінюєш (конституція 3.2).
- Target API 36 може вимагати конкретних версій Android SDK/Build-Tools в образі game-ci — перевір у журналі збірки; якщо образ не має API 36, запиши факт і варіанти (не знижуй target мовчки).
- Підпис: наявні секрети keystore можна використовувати як зараз; keystore колись був в історії git старого проєкту (борг: перегенерувати перед релізом — не в цьому завданні, згадай у звіті).
- Кожен запуск CI — 5–15 хв: групуй зміни, не запускай на кожну дрібницю. Чекай через `gh run watch` / `gh run view`, логи помилок — `gh run view --log-failed` (у звіт лише суть).
- `.asmdef` без жодного скрипта дає попередження Unity — дозволено один файл-заглушку.
- PR >400 рядків рукописного коду — розбити; згенеровані файли (`ProjectSettings`, `.meta`, lock) не рахуються.
