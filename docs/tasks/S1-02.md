## Мета
Робоча дошка в чистому Core: збирання страви з інгредієнтів за рецептом, перевірка правильності, видача готової страви (передача клієнтові — інтерфейс для S1-03).

## Вхідні дані
`docs/design/GAME_DESIGN.md` розд. 3 (станції `bread`, `sauce`, `salad`, `board`, `bin`), розд. 5 (рецепти, правила збирання на дошці), розд. 2 (керування), розд. 12 (Q1); `docs/design/LEVEL_DESIGN.md` (які інгредієнти доступні на яких рівнях); код S1-01 (`Grill`, чергу дій `ShiftSimulation`).

## Що зробити
- Моделі `Board` (дошка), `Ingredient`, `Recipe` (кроки, optional, ціна, надбавки), результат перевірки страви (правильна / хибний порядок / зайвий інгредієнт).
- Команди: взяти піту, покласти м'ясо з гриля на дошку (використати `TakeMeat` із S1-01), додати салат/соус, зняти хибний інгредієнт, очистити дошку у смітник (штраф — параметр), видати страву. Усе через існуючу чергу дій.
- Доступність станцій за рівнем — параметр (`unlockLevel` / набір доступних станцій у конфізі зміни), а не гілки коду.
- Інтерфейс/подія видачі страви для клієнтів (S1-03), без самих клієнтів.
- Числа (час дій, штрафи, надбавки) — лише з конфіга; правила — лише з GAME_DESIGN.md. Неясне → варіанти в `docs/governance/OWNER_INBOX.md` не пиши (зона Агента 0): запиши в журнал картки готовий рядок і найменш ризикове припущення.

  - Конфіг `BoardConfig`: номер рівня `Level`, штраф `ClearPenaltyCoins` (`rules.boardClearPenaltyCoins`), список станцій (`StationConfig`: вид, `unlockLevel`, `actionMs`), інгредієнтів (`Ingredient`: назва, станція, надбавка `ExtraPriceCoins`), рецептів (`Recipe`: назва, кроки, необов'язкові, ціна, `unlockLevel`; інгредієнти названі рядками, як у JSON).   - Доступність — лише порівняння `unlockLevel <= Level` (`BoardConfig.IsStationAvailable`, `IsRecipeAvailable`); гілок коду під рівень немає. Команда до недоступної станції повертає `false` і нічого не змінює (як команда до неіснуючого слота гриля).
  - Дошка приймає будь-який доступний інгредієнт, навіть хибний (інакше нічого було б «знімати»). `Board.Check(out Dish)` дає `Empty` / `Incomplete` / `Correct` / `WrongOrder` / `ExtraIngredient`. Правильна страва = усі кроки рецепта по порядку + будь-яка підмножина необов'язкових у порядку списку `optional`. `ExtraIngredient` — інгредієнта немає в рецепті або він покладений двічі; `WrongOrder` — інгредієнти з рецепта, але порядок хибний, пропущено крок або необов'язковий покладено до завершення кроків.
  - Видача (`ServeDish(target)`): лише для `Correct`; інакше результат дії `BoardEmpty` / `DishIncomplete` / `DishWrongOrder` / `DishExtraIngredient`, дошка не змінюється. Правильна страва передається в `IDishReceiver.TryReceive(Dish, target)`: `true` — дошка порожня, `ServedCount`++, `LastServed`; `false` — `DishNotAccepted`, страва лишається. Без отримувача (старий конструктор) страва завжди «видана».
  - `Dish`: `RecipeIndex`, `OptionalMask` (біт i — i-й необов'язковий рецепта), `PriceCoins` = ціна рецепта + надбавки доданих необов'язкових.

- Припущення (правил у `GAME_DESIGN.md` немає або вони двозначні; обрано найменш ризикове, усе покрито тестами):
  1. **Видати можна лише правильну повну страву.** Розд. 2: «тап по готовій страві». Хибний порядок чи дублікат на дошці видати не можна (гравець знімає інгредієнт або чистить дошку). «Неправильна страва» з розд. 5 (клієнт скаржиться) — це правильна за рецептом страва, яка не відповідає замовленню; це S1-03.
  2. **Зняти тапом можна будь-який інгредієнт** з дошки (за місцем або останній), без штрафу; знятий зникає (м'ясо на гриль не повертається). Розд. 5 каже лише «хибний інгредієнт можна зняти тапом», але дошка не знає замовлення клієнта, тож не знає, який необов'язковий «хибний».
  3. **Порядок необов'язкових фіксований** порядком списку `optional` (салат перед соусом, як у «піта -> м'ясо -> (салат) -> (соус)»); кожен — не більше одного разу; обидва соуси разом дозволені.
  4. **Інгредієнт у рецепті — не більше одного разу** (перевірка конфіга). Подвійного м'яса в Етапі 1 немає.
  5. **Надбавка — окреме число на інгредієнт** (`Ingredient.ExtraPriceCoins`), рахується лише для доданих необов'язкових. Розд. 5: «+ надбавка за кожен доданий елемент», ключа в прикладах конфігів немає.
  6. **Місткість дошки** = довжина найдовшого рецепта (кроки + необов'язкові); окремого параметра немає. Повна дошка: `BoardFull`.
  7. **Штраф за очищення** береться за кожне очищення непорожньої дошки; порожню очистити не можна (`BoardEmpty`, без штрафу).
  8. **Недоступний смітник** (його `unlockLevel` більший за рівень або станції немає): `ClearBoard` повертає `false`. Дошка (`Board`) має бути доступна завжди — інакше помилка конфіга.
  9. **Кілька рецептів:** дошка порівнюється з усіма доступними, береться найкращий результат; рецепт визначається за вмістом дошки, гравець його не обирає.
  10. **Тривалість зняття інгредієнта й видачі** = `actionTimeSec` станції `board` (у розд. 3 одне число на станцію).
