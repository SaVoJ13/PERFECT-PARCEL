## Мета
Рівні 1–5 існують як дані: JSON-конфіги за `LEVEL_DESIGN.md`, чисте завантаження в Core-конфіги (`ShiftConfig`, `GrillConfig`, `BoardConfig`, конфіг клієнтів і розкладу) з суворою валідацією.

## Вхідні дані
`docs/design/LEVEL_DESIGN.md` (повністю), `docs/design/GAME_DESIGN.md` розд. 3–7, 11 (приклади конфігів; нулі в прикладах — «значення визначає симуляція»); код S1-01…S1-03 (конфіг-класи, `GetErrors`), журнали карток S1-01…S1-03 і QA-звіти; ADR-020; `OWNER_INBOX.md` №13–24 (відкриті дизайн-питання: у Core діють значення «А» за замовчуванням — не змінюй, лише виставляй параметри).

## Що зробити
- Файли у `Assets/_Project/Resources/Config/`: `stations.json`, `recipes.json`, `customers.json`, `levels/L01.json … L05.json` (за прикладами розд. 11 і структурою LEVEL_DESIGN розд. 2). Правила — лише з LEVEL_DESIGN/GAME_DESIGN; числа, яких документи не дають, — чернеткові, позначені в журналі як «чернетка, уточнить бот-тест S1-05», у файлах — поле `"draft": true`.
- Розбір JSON без Unity-залежностей у `KebabStreet.Core` (власний мінімальний парсер або `System.Text.Json`, якщо доступний у Unity 6.3 asmdef без нових пакетів; інакше — вирішити й записати в журнал; нових залежностей без запису в `TECH_STACK.md` не додавати). Файли у `Resources/` читає тонка обгортка поза Core (Game/Services), у Core — лише розбір рядка.
- Валідація: помилки з шляхом до ключа; невідомі ключі/рецепти/клієнти, нульові/від'ємні числа, посилання на неіснуючі станції, `unlockLevel` вище рівня; кожен рівень збирається в `ShiftConfig` без помилок `GetErrors`.
- Рівні 1–2 за ADR-020 — параметрами; ключі локалізації лише як ключі (`nameKey`), тексти не додавати.
- Ключ ціль/зірки (`goal`, `stars`) — зчитуються і зберігаються як дані для S1-06; логіку підрахунку не писати.

## Файли, які можна змінювати

Не чіпати інше.

## Критерії приймання
- [ ] Тести EditMode: усі 5 рівнів завантажуються й валідні; кожна категорія помилок валідації має тест з вадним JSON; рівні відповідають таблиці зведення LEVEL_DESIGN розд. 1 (цілі, клієнти, станції, нові механіки); ADR-020 для рівнів 1–2; детермінований розклад із конфіга.
- [ ] Тест «конфіг не містить видимого тексту» (лише ключі).
- [ ] Без `UnityEngine` у Core; старі тести не змінені й не послаблені; CI зелений для останнього коміту.
