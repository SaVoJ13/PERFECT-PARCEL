## Мета
Прогрес гравця надійно зберігається: збій під час запису, пошкоджений файл або стара версія гри не призводять до втрати прогресу чи падіння. Час для щоденних механік береться через `IClock`, щоб переведення годинника не давало повторних нагород. Це фундамент довіри гравця — втрата збереження означає втрату гравця.

## Що зробити
1. **Модель збереження в `Core`** (чистий C#): мінімальний `PlayerProgress`/`SaveData` з полем `schemaVersion` і кількома справжніми полями, потрібними вже зараз (напр. пройдені рівні/зірки, монети, кристали, час останнього збереження) — без вигадування наперед усієї економіки.
2. **Серіалізація в JSON без `UnityEngine` у Core.** Обери спосіб і обґрунтуй у журналі: `Core` має `noEngineReferences: true`, тому `JsonUtility` там недоступний. Нових пакетів додавати не можна (якщо без пакета ніяк — зупинись і опиши варіанти у звіті). Прийнятно: серіалізатор за інтерфейсом із реалізацією в `Services` (де `UnityEngine` дозволено) або невеликий власний код. Формат має бути стабільним і детермінованим (однакові дані → однаковий текст).
3. **`ISaveStorage` у `Services`** + файлова реалізація з **атомарним записом** за `ARCHITECTURE.md` розд. 5: запис у тимчасовий файл → перевірка (читається й розбирається) → поточний файл стає резервною копією → тимчасовий стає основним. Шлях до папки передається ззовні (не `Application.persistentDataPath` усередині логіки) — щоб тестувати на тимчасовій папці. Плюс реалізація в пам'яті для тестів.
4. **Завантаження з відновленням:** основний файл пошкоджений/порожній/обрізаний/відсутній → береться резервна копія; обидва непридатні → чистий профіль **і явний результат «прогрес скинуто»** (щоб UI міг показати повідомлення; жодного мовчазного скидання). Пошкоджений файл не видаляється мовчки — відкладається вбік (напр. `.corrupt`) для діагностики. Результат завантаження — явний тип (звідки завантажено: основний / резервний / новий профіль, чи була міграція).
5. **Версії та міграції:** ланцюжок міграцій `vN → vN+1`; збереження зі старшою версією, ніж знає гра (відкат версії застосунку), **не перезаписується і не псується** — визнач і протестуй безпечну поведінку. Оскільки схема лише народжується, зроби поточною версію 2 і одну справжню невелику міграцію `1 → 2` (напр. додане поле з типовим значенням) — щоб механізм і тест міграції були справжніми, а не порожніми.
6. **`IClock` у `Services`:** поточний час UTC; системна реалізація і керована тестова. **Захист від переведення годинника назад:** у збереженні тримається остання відома позначка часу; якщо годинник показує раніший час, «ефективний» час для щоденних механік не йде назад (нагороду за «новий день» повторно отримати не можна). Зроби це маленькою чистою функцією/сервісом із тестами; самі щоденні нагороди — не в цьому завданні.
7. **Тести EditMode** — щонайменше:
   - зберегти → завантажити → дані ідентичні (round-trip);
   - після другого збереження резервна копія містить попередній стан;
   - пошкоджений основний файл (сміття, обрізаний JSON, порожній) → завантажено з резервної копії, результат це показує, пошкоджений файл відкладено;
   - обидва файли непридатні → чистий профіль + ознака скидання;
   - файлів немає (перший запуск) → чистий профіль без ознаки помилки;
   - збій посеред запису (імітація: лишився тимчасовий файл / виняток під час запису) → попередні дані цілі;
   - міграція `1 → 2`: зафіксований текст збереження v1 у тесті → коректний v2; тест на **кожну** міграцію;
   - збереження з майбутньою версією не перезаписується;
   - невідомі поля в JSON не ламають завантаження (визнач поведінку);
   - годинник: час назад → ефективний час не зменшується; час уперед → нормальний хід;
   - серіалізація детермінована.

## Ризики / на що звернути увагу
- `File.Replace`/`File.Move` поводяться по-різному на Windows, Linux і Android — обери послідовність, що працює на Android (IL2CPP) і в CI на Linux; на телефоні це буде перевірено пізніше (E0-12 / Етап 1) — познач «НЕ ПЕРЕВІРЕНО на пристрої».
- IL2CPP обрізає невикористаний код (stripping) і не підтримує динамічну генерацію коду: серіалізація через рефлексію може працювати в редакторі й зламатися в збірці. Обирай спосіб, безпечний для IL2CPP, і запиши ризик.
- Культура/локаль: числа й дати в JSON — завжди інваріантна культура (`CultureInfo.InvariantCulture`), час — UTC у цілих одиницях (напр. Unix-секунди).
- Не роби шифрування, контрольні суми «проти читерів», хмарні збереження — не в обсязі.
