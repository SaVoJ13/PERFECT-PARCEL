## Мета
Частина екрана зміни, у яку можна грати: UI Toolkit (D-03), портретна орієнтація, керування тапами, **поверх готового `KebabStreet.Core` через `ShiftDriver` (S1-08), без дублювання логіки в UI**. Усі видимі тексти — ключі локалізації EN/UK/PL.

## Вхідні дані

## Що зробити
- Станція збирання: кнопки пити, салатів, соусів (за рівнем), дошка з поточними інгредієнтами, зняття тапом (PROVISIONAL 17), очистити дошку, скасувати.
- Видача: тап «Видати» клієнту; показ результату (правильно/хибна страва), комбо.
- Вся грі придатна від початку до кінця зміни на рівнях 1–5; на кінці — мінімальний підсумок, що вже є.
- Додано Керівником 2026-11-13 (вписав Агент 3 за дорученням):
  - BUG-040: ширину карток прилавка рахувати від ширини зони/екрана — 3 картки в один рядок на 1080x2340, 12 слотів не ламають розкладку (за потреби скорочувати).
  - BUG-037: тап по слоту гриля, що ігнорується (сире/готується), показує коротку підказку (ключ EN/UK/PL).
  - За QA S1-09b: окремо модель вигляду з тестами і панель UI (PR ≲400 рядків коду, якщо реально; інакше обґрунтувати).
  - Ключовий тест: бот-експерт проходить L01 лише через ті самі тапи, що й UI.

- [ ] Тест: тапи збирання/видачі проходять у Core і змінюють знімок очікувано (інтеграційний тест драйвера + моделі вигляду).
- [ ] Тест: повна зміна рівня 1 «ботом через ті самі тапи, що й UI» доходить до `ShiftResult`.
- [ ] Дошка показує інгредієнти в порядку, зняття працює.
- [ ] Автотест: контролер/модель вигляду без Unity-об'єктів, де можливо (стан знімка → дані для показу), і тест «усі ключі є в усіх мовах» зелений.
- [ ] Тапи йдуть лише в `ShiftDriver.Tap`; жодної ігрової логіки в `Views`.
- [ ] CI зелений для останнього коміту; тестів не менше, ніж на базі; жодного вимкненого.
