# ПОРІВНЯЛЬНИЙ АНАЛІЗ ТЕХНОЛОГІЧНОГО СТЕКУ ТА РУШІЇВ (ENGINE COMPARISON)

> **Фаза:** Phase 0 — Планування та архітектура  
> **Автори:** Agent 0 (PM & Architect), Agent 3 (Gameplay Dev), Agent 4 (Platform & Monetization)  
> **Мета:** Обґрунтувати вибір рушія для проєкту з урахуванням 5 строгих критеріїв Master Roadmap 1.4.

## 1. ВСТУП ТА КАНДИДАТИ

Для реалізації казуального 2D-сортувальника посилок на Android було відібрано трьох найсильніших кандидатів:
1. **Unity 2D (C# / URP 2D)** — світовий стандарт комерційного мобільного 2D/3D геймдеву.
2. **Godot 4.3+ (GDScript / C#)** — провідний відкритий легковаговий рушій із прозорими текстовими файлами сцен.
3. **Defold (Lua / C++)** — високопродуктивний, спеціалізований 2D-рушій, орієнтований виключно на мобільні та веб-ігри з нульовим оверхедом.

## 3. ДЕТАЛЬНИЙ АНАЛІЗ РУШІЇВ

### 3.1. Unity 2D (C#)
- **Переваги:**
  - Офіційний плагін Google Mobile Ads з гарантованою підтримкою UMP (GDPR) — це критично для відсутності проблем із комплаєнсом у Google Play.
  - Неймовірна якість коду, який генерують AI-агенти (C# строга типізація, повна підтримка архітектурних патернів).
  - Готова 2D фізика та високоефективна система спрайтової анімації.
- **Вразливості:**
  - Складність налаштування GitHub Actions безкоштовно без інтерактивної активації ліцензії (вирішується використанням `game-ci/unity-builder` з одноразовим `.ulf` файлом або токеном).
  - Більший початковий розмір додатку (~30 МБ) та споживання пам'яті.

### 3.2. Godot 4.3 (GDScript / C#)
- **Переваги:**
  - Повна свобода від ліцензійних вимог і роялті (чистий MIT).
  - Ідеальна інтеграція в Git та CI/CD: headless-експорт працює прямо з консолі Linux без Docker чи ліцензій.
  - Текстові файли сцен (`.tscn`) легко генеруються та валідуються AI.
- **Вразливості:**
  - **Критичний ризик монетизації:** Google не підтримує Godot офіційно. Інтеграція AdMob вимагає кастомних плагінів Android Gradle (`.aar`), які можуть ламатися при оновленні Target SDK 34+.
  - Галюцинації AI: моделі часто плутають синтаксис Godot 3 і Godot 4.

### 3.3. Defold (Lua)
- **Переваги:**
  - Екстремальна оптимізація: 60 FPS на будь-якому «калькуляторі», розмір білда до 10 МБ.
  - Миттєва збірка в GitHub Actions через `bob.jar`.
- **Вразливості:**
  - Lua менш строго типізований, що ускладнює підтримку складної мета-економіки командою агентів.
  - Менша доступність готових бібліотек і слабша підтримка медіації реклами.

## 4. СТРАТЕГІЧНИЙ ВИСНОВОК ТА РЕКОМЕНДАЦІЯ AGENT 0

Головна мета PERFECT PARCEL — **успішний комерційний F2P-реліз у Google Play із стабільною рекламою (Rewarded/Interstitial) та проходженням перевірки Google Data Safety / GDPR без сюрпризів**.

1. **Рекомендований вибір:** **Unity 2D (C# LTS, наприклад 2022.3 LTS або 6000.0 LTS)**.
   - *Чому:* Єдиний рушій із бездоганною офіційною підтримкою Google Mobile Ads SDK та UMP. Для ШІ розробка на C# дає найвищу точність і стабільність коду без застарілих синтаксичних помилок.
   - *План компенсації недоліків:* Питання CI/CD вирішується через стандартний Game-CI GitHub Actions workflow із секретами репозиторію; питання оптимізації вирішується пулінгом об'єктів (Object Pooling) та оптимізацією текстур спрайтів у Sprite Atlas.

2. **Запасний безкоштовний варіант:** **Godot 4.3 (GDScript)**.
   - Якщо Власник категорично не бажає мати справу з ліцензійною угодою Unity або заставкою Unity Splash Screen — обирається Godot 4.3 з використанням community-плагіна `poing-studios/godot-admob-android`.
