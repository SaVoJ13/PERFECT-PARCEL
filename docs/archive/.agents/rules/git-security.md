# ПРАВИЛО: КЕРУВАННЯ ВЕРСІЯМИ, БЕЗПЕКА ТА СЕКРЕТИ (GIT & SECURITY)

> **Статус:** Обов'язкове для всіх AI-агентів проєкту PERFECT PARCEL  
> **Версія:** 1.4  
> **Джерело:** Розділ 7 Roadmap 1.4  

---

## 1. СТРУКТУРА ГІЛОК ТА РОБОЧИЙ ПРОЦЕС (GIT FLOW)

1. **Гілка `main` (Production/Stable):**
   - Завжди стабільна, компільована та протестована.
   - Прямі коміти в `main` суворо заборонені (лише злиття перевірених гілок).
   - Кожен реліз тегується версією (наприклад, `v1.0.0-mvp`).
2. **Робочі гілки (`feature/*`, `fix/*`, `docs/*`):**
   - `docs/phase-0-setup` — для робіт з документації.
   - `feature/conveyor-mechanic` — для розробки геймплею.
   - `fix/sorting-hitbox-p1` — для виправлення дефектів.
3. **Стандарти комітів:**
   - Чіткі описи у форматі Conventional Commits:  
     `feat(core): implement parcel spawn pooling`  
     `docs(design): update level 1-30 difficulty curve`  
     `fix(save): prevent json corruption on exit`

---

## 2. ПОЛІТИКА БЕЗПЕКИ ТА ЗАХИСТУ СЕКРЕТІВ

- 🚫 **Категорична заборона на відкриті секрети:**
  - Ніколи не комітити у Git API-ключі, App ID реклами, паролі або токени доступу.
  - Усі чутливі змінні конфігуруються через `.env`, локальні нетрекані файли або GitHub Secrets.
- 🔑 **Android Release Keystore:**
  - Файли ключів підпису (`*.keystore`, `*.jks`) обов'язково вносяться у `.gitignore`.
  - Зберігання релізного ключа та паролів є персональною відповідальністю Власника.
  - Для CI/CD ключ шифрується у Base64 і додається у GitHub Repository Secrets.

---

## 3. СТАНДАРТ `.gitignore`

Репозиторій повинен містити надійний `.gitignore`, що виключає:
- Системні тимчасові файли (`.DS_Store`, `Thumbs.db`).
- Кеш IDE (`.vs/`, `.idea/`, `.vscode/`).
- Тимчасові файли збірки (`Build/`, `build/`, `bin/`, `obj/`, `Library/`, `Temp/`).
- Ключі підпису (`*.keystore`, `*.jks`).
- Локальні файли конфігурацій з паролями (`local.properties`).

---

## 4. СТРАТЕГІЯ CI/CD (GITHUB ACTIONS)

- Автоматичний запуск лінтерів, тестів та збірки APK на кожен Pull Request.
- Готовий тестовий APK публікується як GitHub Actions Artifact з терміном зберігання до 14 днів.
- **Жодна дія автоматично не публікує збірку в Google Play Store без прямої команди та підтвердження Власника.**
