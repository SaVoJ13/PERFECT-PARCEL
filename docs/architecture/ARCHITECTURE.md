# KEBAB STREET — Архітектура (Етап 0)

**Власник документа:** Агент 0. Зміни — через `DECISIONS.md`.
**Стан:** цільова архітектура нового проєкту. Старий код PERFECT PARCEL не використовується.

## 1. Принципи
1. **Логіка окремо від Unity.** Уся симуляція зміни (клієнти, терпіння, гриль, станції, замовлення, монети, зірки) — у збірці `KebabStreet.Core` без залежності від `UnityEngine`. Її можна запускати в автотестах і в бот-тесті тисячі разів за секунди.
2. **Детермінований такт.** Симуляція рухається кроками `Tick(deltaTime)` з фіксованим кроком і генератором випадковості з seed. Один seed + однакові дії гравця = однаковий результат. Це робить помилки відтворюваними.
3. **Unity лише показує і передає ввід.** `MonoBehaviour`-«в'юхи» читають стан симуляції і відправляють команди (`TapStation`, `ServeCustomer`…). Жодних правил гри у в'юхах.
4. **Дані в конфігах** (JSON у `Assets/_Project/Resources/Config/`), тексти — в локалізації.
5. **Headless-first.** Сцени, префаби й налаштування імпорту створюються/перевіряються Editor-скриптами в CI.
6. **Сервіси за інтерфейсами:** реклама, покупки, аналітика, збереження, час — замінні заглушками.

## 2. Збірки (asmdef)
| Збірка | Залежить від | Що містить |

| `KebabStreet.Core` | — (чистий C#) | Модель зміни, станції, клієнти, замовлення, економіка, прогрес, валідація конфігів |
| `KebabStreet.Services` | Core | Інтерфейси `IAdsService`, `IPurchaseService`, `IAnalyticsService`, `ISaveStorage`, `IClock` + заглушки |

## 4. Головні поняття Core (орієнтир, не остаточні назви)
- `ShiftSimulation` — один рівень: такт, таймер зміни, черга клієнтів, станції, рахунок, умови зірок і поразки.
- `Station` — гриль (стан м'яса: сире → готове → пригоріле), фритюрниця, хліб, салат, соуси, напої, столики, пакування.
- `Recipe` — страва як послідовність інгредієнтів/кроків; `Plate` — що зараз зібрано на дошці.
- `Customer` — тип, замовлення, особливе прохання, терпіння, чайові.
- `Wave` / `SpawnSchedule` — коли і які клієнти приходять (із конфігу рівня).
- `Booster` — тимчасовий модифікатор симуляції.
- `PlayerProgress` — пройдені рівні, зірки, валюти, покращення, декор, досягнення, щоденні дані.
- `EconomyService` — нарахування/списання з журналом транзакцій (захист від подвійних нагород).

## 5. Збереження
JSON у `Application.persistentDataPath`; запис у тимчасовий файл → перевірка → резервна копія → заміна. Поле `schemaVersion`; кожна зміна схеми — міграція + тест. Пошкоджений файл → відновлення з резервної копії, інакше чистий профіль із повідомленням.
Час для щоденних механік — через `IClock`; переведення годинника назад не дає повторних нагород.

## 6. Бот-тест рівнів
`LevelSolvabilityTests` проганяє кожен рівень із конфігу двома ботами (ідеальний і «середній» з затримками й помилками) з кількома seed, без бустерів і з мінімальними покращеннями. Рівень, який «середній» бот не проходить хоча б на 1★, — помилка дизайну.

## 7. Що свідомо відкладено
Сервер, акаунти, хмарні збереження, аддресабли/завантаження контенту з мережі (кандидат для оновлень локацій — окреме рішення на Етапі 7).
